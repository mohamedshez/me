# shez.app implementation rules

- Read and apply `docs/big-o-agent-guide.md` when changing Next.js, React, or TypeScript. Report time, space, and framework boundaries when presenting code changes.
- Interpret Big O accurately: Map lookups are average O(1) after O(n) index construction; arbitrary substring search cannot be converted to O(1) with a name index. Document unavoidable scans and text-length costs.
- Use Tailwind CSS 4 for styling. Preserve the Engineering Blueprint design, responsive layout, keyboard access, theme switching, and reduced motion.
- Keep unneeded repository data out of Client Components. Server Components perform normalization, merging, indexing, and recent selection. Keep directory rendering bounded through pagination.
- Only personal work and approved personal biography may appear on the public site. Preserve the existing server exclusion policy and tests; never ingest external company/bio/README fields or private repository data.
- Keep GitHub revalidation and long-lived tab refresh at 24 hours. No five-minute polling.
- Run type checks, policy/algorithm tests, production build, and relevant browser checks before shipping changes affecting these boundaries.
- Keep deployment versions generated by `scripts/build-version.mjs`. Production CI tests one build, tags its exact commit, and deploys the same prebuilt output. Never overwrite a build tag or enable a parallel Vercel Git deployment path.

- Batch small changes into deliberate production releases. Main pushes and PRs run checks only; release only via explicit workflow_dispatch on main. Keep Vercel Git auto-deploy disabled, preserve the rolling 24-hour 99-deployment budget guard, and tag each tested production artifact. Daily content refresh must not create deployments.
